# Secure Chat — протокол и развёртывание

[English](secure-chat.md) · [Security test report](../public/secure-chat/reports/security-tests.md) · [Review and remediation](../public/secure-chat/reports/review-closeout.md)

Одна ссылка, одна беседа, до 24 часов. Текст и эмодзи. Ключи создаёт браузер. Без аккаунтов, администраторов, вложений, архива и восстановления.

## Временная личность

Браузер создаёт отдельный ключ чата для подписей Ed25519 и одноразовый MLS KeyPackage. Базовое удостоверение MLS содержит SHA-256 публичного ключа подписи. Подписанный профиль связывает никнейм, ключ, конкретную беседу и её срок. Клиент проверяет уникальность никнеймов без учёта регистра. Полный отпечаток определяет временный ключ, а не личность человека.

## Секрет приглашения

Ссылка содержит случайный секрет длиной 256 бит, случайный идентификатор беседы, первый публичный ключ подписи и общий срок после #. Фрагмент удаляется из текущей записи истории. HKDF-SHA-256 выводит отдельные ключи для шифрования подключения и допуска к транспортному серверу. Исходный секрет серверу не передаётся. Первый участник подписывает зашифрованное название; особых прав этот ключ не даёт. Список участников содержит подписанную цепочку допуска, привязанную к первому ключу: обладатель ссылки не может подменить беседу группой с другим основателем.

## Вход без аккаунта

Отдельный транспортный ключ P-256, созданный в браузере, подписывает одноразовый запрос со сроком 60 секунд. В нём закреплены origin, беседа, срок, публичный транспортный ключ, хеш допуска и данные создания. Сервер удаляет запрос до проверки и выдаёт случайный токен длиной 256 бит. Гость передаёт зашифрованный подписанный MLS KeyPackage. Участник с открытой вкладкой автоматически добавляет его через MLS Add и защищённый HPKE пакет Welcome. Гость получает будущие сообщения без прежней истории. Возможности у всех одинаковые. Подпись всего KeyPackage и MLS-предложение проверяются до захвата права записи. Повреждённый запрос отклоняется без отключения участников; незавершённый вход освобождает место через две минуты.

## Messaging Layer Security

Используется закреплённая версия ts-mls 1.6.4 и набор RFC 9420 MLS_128_DHKEMX25519_AES128GCM_SHA256_Ed25519: X25519, AES-128-GCM, SHA-256 и Ed25519. MLS проверяет целостность группового протокола и выводит отдельные поколения ключей сообщений. Дополнительная подпись связывает отпечаток отправителя, идентификатор, текст, беседу и срок. Проверки выполняются до показа текста. Публичные MLS-сообщения, неподдерживаемые операции, оборванные пакеты и лишние байты отклоняются. Подпись приложения также связана с эпохой, а отправитель сверяется с аутентифицированным MLS-ключом: участник не может заново упаковать чужой текст и выдать его за сообщение автора.

## Обновление ключей

Подключение гостя меняет эпоху MLS. Каждый активный клиент также обновляет собственный ключ примерно раз в пять минут; новый участник делает это при следующем опросе. Прежние эпохи и использованные поколения ключей не сохраняются. Операции клиента последовательны. До шифрования он получает краткосрочное право записи на сервере; при сбое повторяется только тот же шифротекст. Если результат отправки остаётся неизвестным, вкладка уничтожает своё состояние и предлагает подключиться заново. Отката криптографического состояния нет. Небольшой адаптер закреплённой версии явно исключает старые эпохи и сохраняет проверенного отправителя. Настройки нулевого хранения библиотеки оказалось недостаточно — это выявлено и исправлено при проверке.

## Общий срок

Создатель задаёт одно название и получает одну ссылку. Ключ связан только с одной беседой. У всех общий срок — не более 24 часов с создания. Подключения и обновления ключей не продлевают его. Раз в секунду и при запросах сервер удаляет истёкшие беседы, шифротекст, допуски, запросы на подпись и привязки. Нет базы чата, файлового архива и резервных копий. Перезапуск очищает активные беседы раньше. Сервер хранит не более 256 событий или 1 000 000 символов зашифрованных событий на беседу, вкладка — не более 256 прочитанных сообщений в памяти.

## Минимум метаданных

Никнеймы, название беседы, MLS KeyPackage и списки участников шифруются до передачи. Сервер видит временные транспортные идентификаторы, связь с беседой, операции подключения, размеры пакетов и время. Короткие сообщения дополняются до целевого размера MLS-содержимого в 1 024 байта; более длинные всё ещё различаются по размеру. Чат не использует cookies, localStorage, IndexedDB, аналитику, загрузку приватных ключей и вложения.

## Изоляция и лимиты

Отдельный relay-контейнер не получает файлы и секреты сайта, постоянный диск, опубликованный порт или обычный выход в интернет. Файловая система только для чтения, пользователь без root, все Linux capabilities сняты, no-new-privileges; лимиты — 192 МиБ памяти, одно ядро и 32 процесса. Шлюз обращается к фиксированному внутреннему адресу и не передаёт IP-заголовки и cookies. Ограничения: 16 бесед, 16 допущенных транспортных идентификаторов на беседу, 256 сессий, 512 привязок ключей, 64 запроса на подпись, восемь ожидающих гостей на беседу, четыре параллельные проверки подписи и 16 МБ строк событий на весь relay.

## Отдельный вход через Tor

В Tor Browser можно открыть отдельный v3 onion-адрес. Используются тот же сервер и сеть Tor; второй арендованный узел и выходной узел не нужны. Ограниченный Tor-сервис передаёт запросы только локальному шлюзу чата. Onion-маршрут открывает чат, security и необходимые статические ресурсы, но не остальные API сайта. Ключ самого onion-сервиса хранится постоянно для стабильного адреса и не содержит переписки. HTTPS- и onion-адреса разрешаются явно, с отдельной проверкой Origin.

## Условия и ограничения

### У прямой секретности есть условия

Использованные поколения ключей и прежние эпохи удаляются. Копия состояния участника не перестаёт работать только потому, что обновился другой участник. Для восстановления защиты нужен честный выпуск нового ключа пострадавшим клиентом после потери злоумышленником доступа к устройству. Этот набор алгоритмов не постквантовый. Мы не заявляем превосходство или эквивалентность Signal и не выдаём эту интеграцию или ts-mls за независимо проверенную реализацию.

### Клиентский код остаётся точкой доверия

Взломанный сайт, расширение, браузер или устройство могут похитить текст и действующие ключи. MLS не защищает от вредоносного JavaScript, выданного владельцем сервера. Недобросовестный relay может задерживать, скрывать или разделять доставку. Сравнение кода беседы помогает заметить разные состояния, но не заменяет внешний журнал прозрачности. Полные отпечатки и код беседы следует сверять через другой доверенный канал.

### Ссылка даёт доступ

Любой обладатель полной ссылки может войти, пока участник онлайн и есть место. Отзыва доступа, модерации и служебного восстановления нет. Закрытие вкладки не отзывает скопированное приглашение. Если все потеряли ключи, сервер не восстановит беседу. Вернувшийся пользователь создаёт новую временную личность.

### Удаление ограничено участниками системы

При истечении срока приложение удаляет активные ссылки на состояние и по возможности обнуляет изменяемые буферы ключей. JavaScript и браузер не гарантируют физическое стирание памяти. Участники могут сохранить сообщения и снимки экрана, а недобросовестный хост — записать шифротекст или метаданные. Восстановления средствами приложения нет, но чужие копии код удалить не может.

### Анонимность не означает невидимость

При обычном HTTPS сетевой узел видит адрес подключения даже без access-логов. VPN заменяет его адресом своего выхода. Tor Browser может разделить сеть пользователя и адрес назначения; корреляция времени, раскрытая ссылка и взломанный клиент всё равно остаются рисками. Транспортные идентификаторы и рисунок трафика доступны relay.

### Доступность ограничена намеренно

Общие квоты и лимиты сессий снижают перегрузку без хранения IP, но не исключают массовое создание ключей. Приглашённый злоумышленник может мешать беседе. Для подключения гостя нужен участник онлайн в течение двухминутного окна. Вкладке, пропустившей больше сохранённого окна событий, нужен новый ключ. Шифрование не гарантирует доставку и защиту от отказа в обслуживании.

```sh

npm run lint
npm run build
# Isolated local preview:
CHAT_LOCAL_PREVIEW=1 docker compose up -d --build
CHAT_TEST_ORIGIN=http://127.0.0.1:3000 node --experimental-strip-types scripts/check-secure-chat.mjs
```

HTTP-проверка создаёт три временных тестовых ключа. Служебного обхода очистки нет: её зашифрованное состояние истекает обычным способом. Отчёт отличает перевод тестовых часов от реального суточного прогона.

## Production operations

Используйте production override без флага локального preview. Соберите образ с неизменным идентификатором ревизии, запустите кандидат на отдельном loopback-порту, проверьте и переключите шлюз. Сохраните прошлый образ и nginx для отката. Не передавайте relay секреты или постоянные данные сайта. У сайта могут быть другие постоянные сервисы — они изолированы от чата. Перезапуск или замена relay завершает текущие беседы.

В nginx должны быть отключены access-логи сайта и логи ошибок запросов чата, ограничены тела запросов, удалены IP-заголовки и cookies на маршруте API, задан точный HTTPS origin. Старые логи и журналы провайдера не входят в эту функцию и не удаляются скрытно. Tor открывает только локальный шлюз чата; его постоянный ключ адреса отделён от временной переписки. Ядро хоста, Docker, сеть провайдера и выдаваемый frontend остаются точками доверия.
