# Secure Chat

**Одна ссылка. Ключи в браузере. До 24 часов.**

Временный групповой чат на MLS (RFC 9420). Выберите никнейм, создайте ключи в браузере и отправьте приглашение друзьям. Гость создаёт собственные ключи, действующий участник автоматически подключает его. Текст, эмодзи, зашифрованные ответы и реакции. Интерфейс EN/RU. Без аккаунтов, вложений, администраторов и постоянного восстановления.

## Технология

Используется `ts-mls` 1.6.4: X25519, AES-128-GCM, SHA-256 и Ed25519. Никнеймы и список участников зашифрованы; подписи и цепочка допуска связаны с первым ключом беседы. Секрет приглашения передаётся после `#`, удаляется из текущей записи истории и не отправляется серверу. HKDF разделяет шифрование подключения и транспортный допуск.

Ключи сообщений обновляются, старые эпохи исключаются из состояния. Небольшой адаптер закреплённой библиотеки проверяет настоящего MLS-отправителя и явно удаляет прежние эпохи. При неизвестном результате записи повторяется только тот же шифротекст; небезопасного отката состояния нет.

Один общий срок, не более 24 часов, до 16 участников. Relay хранит ограниченное состояние в RAM. Он работает в отдельном Docker без постоянных томов, секретов сайта, опубликованных портов и обычного выхода в интернет. Дополнительный onion-вход использует Tor на том же сервере. Постоянный ключ адреса Tor отделён от временной переписки.

## Запуск

Node 22.18+ и Docker Compose:

```sh
npm ci
npm run test:chat:report
npm run lint
npm run build
CHAT_LOCAL_PREVIEW=1 docker compose up -d --build
```

Откройте [localhost:3000/secure-chat](http://localhost:3000/secure-chat). Для production задайте точный HTTPS `CHAT_ORIGIN` в `.env` и `CHAT_LOCAL_PREVIEW=0`. Публичный доступ идёт через TLS reverse proxy, порт приложения остаётся на loopback. Подробности и границы изоляции — в [документации](docs/secure-chat.ru.md).

## Что проверено

Отчёт содержит выполненные тесты, TAP, дату, среду и SHA-256 кода. Шесть проблем предварительной версии исправлены и покрыты отдельными регрессионными сценариями. Проверяются реальные клиенты и relay: вход, 16 участников, отправка, подмена подписей, повреждение пакетов, гонки, повторные запросы, лимиты, срок и очистка. Отдельно проверены сценарии кражи MLS-состояния. Проверка 24 часов использует тестовые часы; это не суточный нагрузочный прогон.

Это самопроверка, **не независимый аудит**. Нет заявления о превосходстве над Signal или постквантовой защите. Взлом сайта или устройства раскрывает действующие ключи и текст. Приглашённый злоумышленник может мешать беседе. После кражи состояния нужно честное обновление ключа самим пострадавшим клиентом после потери доступа злоумышленником. Физическое стирание памяти браузера и удаление чужих копий не гарантируются.

Своя ссылка в том же профиле браузера и на том же origin подключает открытую сессию: исходная вкладка хранит ключи и выполняет все операции MLS. Её нужно оставить открытой. Закрытие или перезагрузка исходной вкладки теряет ключи; после этого вернувшийся посетитель создаёт новую временную личность. Знакомый никнейм не подтверждает человека — сверяйте полный отпечаток через другой канал. Для аудита или сообщения об уязвимости: [Telegram DM](https://t.me/mailsec).

## Возврат и участники

Сессия продолжает работать при переходах внутри сайта. Повторное открытие чата возвращает тот же ключ и историю; фоновая вкладка продолжает подключать гостей. В списке участников видны статусы онлайн, подключения и потери связи. Никнеймы и привязки транспортных соединений остаются в подписанных зашифрованных профилях. Статус relay справочный: он не подтверждает личность и не отзывает ключи. Закрытие или перезагрузка исходного документа по-прежнему уничтожает ключи.
